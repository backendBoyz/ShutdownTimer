# Building the Python app

The generated PyInstaller output (`build/`, `dist/`, `__pycache__/`) is **not**
checked into git (see `.gitignore`). This file explains how to regenerate it
locally whenever you need a standalone `.exe`.

## Prerequisites

- Windows 10/11
- Python 3.9+ (3.11 recommended)
- Dependencies:
  ```bash
  pip install customtkinter pyinstaller pywin32
  ```

## Run from source (no build needed)

```bash
cd python
python sleep.py
```

## Building a standalone .exe

The repo ships three PyInstaller spec files that all package the same
entry point (`sleep.py`) under different output names/icons:

| Spec file             | Output name       | Icon               |
| ---------------------- | ----------------- | ------------------ |
| `sleep.spec`            | `sleep.exe`        | default            |
| `ShutdownTimer.spec`    | `ShutdownTimer.exe`| default             |
| `ShutdownMikmer.spec`   | `ShutdownMikmer.exe`| `assets/icon.ico`  |

From the `python/` directory, build any of them with:

```bash
pyinstaller ShutdownMikmer.spec
```

This recreates `build/ShutdownMikmer/` (intermediate PyInstaller working
files) and `dist/ShutdownMikmer.exe` (the final executable).

If you'd rather build from scratch without a spec file:

```bash
pyinstaller --name "ShutdownTimer" --onefile --noconsole --icon assets/icon.ico sleep.py
```

Add extra bundled resources with `--add-data "path;."` if needed.

## Notes

- `console=False` in every spec means no terminal window pops up when the
  built `.exe` runs.
- If Windows Defender flags the `.exe`, sign it or add an exclusion — this
  is a common false positive with PyInstaller-built binaries.
- `python/ReleaseV1/` holds a previously published build (`ShutdownMikmer.exe`
  + `ShutdownMikmer.zip`) kept for historical reference; it is not
  regenerated by the steps above.
